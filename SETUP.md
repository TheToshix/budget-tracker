# Инструкция по установке и запуску

Подробный пошаговый гайд, как запустить проект у себя на компьютере и
задеплоить его. Рассчитан на то, что раньше вы этого не делали —
каждая команда объяснена.

Если что-то из терминологии непонятно (что такое npm, зачем нужен
Vite и т.п.) — не страшно, это всё объясняется по ходу.

---

## Что понадобится

1. **Node.js** — среда для запуска JavaScript вне браузера. Через неё
   ставятся все инструменты сборки. Нужна версия **22 или новее** —
   этого требует тестовый фреймворк Vitest, самому приложению хватило
   бы 20.19. Скачать: https://nodejs.org — берите **LTS** (не «Current»).
2. **Git** — чтобы скачать репозиторий. Скачать: https://git-scm.com.
3. **Редактор кода** — например, [VS Code](https://code.visualstudio.com/) (бесплатный).
4. **Терминал** — на macOS/Linux это стандартный Terminal, на Windows
   лучше всего [PowerShell](https://learn.microsoft.com/ru-ru/powershell/) (уже встроен) или терминал внутри VS Code
   (`` Ctrl+` ``).
5. Аккаунт на **GitHub** (нужен на последнем шаге, для деплоя) —
   опционально, если пока просто хотите запустить локально.

Проверить, что всё установилось, — в терминале:

```bash
node -v
npm -v
git --version
```

Все три команды должны напечатать номер версии (например, `v20.11.0`,
`10.2.4` и `git version 2.43.0`). Если пишет «command not found» —
программа не установлена или нужно перезапустить терминал после
установки.

---

## Шаг 1 — Скачать проект

В терминале перейдите в папку, где хотите его держать, и выполните:

```bash
git clone https://github.com/TheToshix/budget-tracker.git
cd budget-tracker
```

`git clone` скачивает репозиторий целиком; `cd` заходит внутрь
скачанной папки. Все следующие команды выполняются оттуда.

Если у вас нет Git, можно скачать архив кнопкой «Code → Download ZIP»
на странице репозитория и распаковать его.

---

## Шаг 2 — Установить зависимости

```bash
npm install
```

Эта команда читает `package.json` и скачивает всё, что нужно проекту:
React, Vite, Recharts, иконки, тестовый фреймворк. Займёт минуту.
Появится папка `node_modules/` — она в `.gitignore` и в репозиторий не
попадает, поэтому её и приходится создавать локально.

Больше ничего настраивать не нужно: адаптер хранилища, Tailwind и
конфигурация тестов уже лежат в репозитории.

---

## Шаг 3 — Запустить и проверить

```bash
npm run dev
```

Терминал напечатает что-то вроде `Local: http://localhost:5173/`.
Откройте эту ссылку в браузере — должно открыться приложение,
гроссбух с формой добавления записи.

**Проверьте:**
- добавляется расход и доход;
- после перезагрузки страницы (`F5`) данные не пропадают — они лежат
  в `localStorage` браузера;
- переключается тема в настройках;
- открывается меню кошельков.

Остановить сервер — `Ctrl+C` в терминале.

Если что-то не работает — см. раздел «Частые проблемы» ниже.

---

## Шаг 4 — Прогнать автотесты и линтер

Проект собран как QA-кейс, поэтому проверки — часть обычного рабочего
цикла, а не что-то опциональное:

```bash
npm test        # 44 автотеста, разово
npm run lint    # статический анализ кода
```

`npm test` должен закончиться строкой вида `Tests  44 passed (44)`.
Во время работы над кодом удобнее держать запущенным
`npm run test:watch` — он перезапускает тесты при каждом сохранении.

Те же три проверки (линтер, тесты, сборка) выполняются автоматически
на GitHub при каждом push и pull request — см. `.github/workflows/ci.yml`.

---

## Шаг 5 — Собрать production-версию

Когда всё проверено локально, соберите финальные файлы для деплоя:

```bash
npm run build
```

Появится папка `dist/` — это и есть готовый статический сайт: набор
HTML/CSS/JS файлов, которые можно разместить на любом хостинге.
Проверить сборку локально:

```bash
npm run preview
```

---

## Шаг 6 — Выложить в интернет (по желанию)

Самый простой вариант — **Vercel** (бесплатно для личных проектов):

1. Зарегистрируйтесь на https://vercel.com через GitHub-аккаунт.
2. Если работаете со своей копией проекта — сделайте форк репозитория
   на GitHub (кнопка «Fork») или залейте свою версию, см. ниже.
3. На Vercel: «Add New… → Project» → выбрать репозиторий → Deploy.
   Vercel сам определит, что это Vite-проект, и всё соберёт.

Альтернативы: Netlify (аналогично Vercel) или GitHub Pages
(потребует чуть больше ручной настройки `vite.config.js`).

### Как залить свою копию на GitHub

Если вы скачивали архивом или хотите вести проект в своём
репозитории, создайте на github.com новый пустой репозиторий
(кнопка «New repository», без README и .gitignore — они уже есть),
затем в папке проекта:

```bash
git remote set-url origin https://github.com/ВАШ_ЛОГИН/budget-tracker.git
git push -u origin main
```

Если репозиторий скачивался архивом и Git в папке ещё не
инициализирован, сначала выполните:

```bash
git init
git add .
git commit -m "Первый коммит: Budget Tracker"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/budget-tracker.git
git push -u origin main
```

## Частые проблемы

**«command not found: npm»**
Node.js не установлен или терминал не видит его после установки —
закройте и откройте терминал заново, при необходимости переустановите
Node.js с https://nodejs.org.

**Предупреждение `EBADENGINE` или ошибка про версию Node**
Проверьте `node -v`. Нужна версия 22 или новее: на Node 20 не
запустится Vitest, а ниже 20.19 — и сам Vite.

**Белый экран в браузере, в консоли (`F12` → Console) ошибка импорта**
Обычно это значит, что `npm install` не отработал до конца. Удалите
папку `node_modules/` и выполните `npm install` заново. Файл
`package-lock.json` при этом трогать не нужно — он фиксирует точные
версии зависимостей.

**Стили не применяются, всё выглядит «голым» HTML без вёрстки**
Tailwind подключён CDN-скриптом в `index.html` и грузится из сети —
проверьте интернет-соединение и что запрос к `cdn.tailwindcss.com` не
блокируется расширением браузера или корпоративной сетью.

**Данные пропадают при перезагрузке страницы**
Приложение хранит их в `localStorage` под ключом
`budget-tracker:budget-tracker:v4`. Данные не сохранятся, если браузер
открыт в приватном режиме или настроен блокировать данные сайтов.

**`npm test` падает, хотя код не меняли**
Убедитесь, что зависимости установлены полностью (`npm install`) и
версия Node — 20 или новее. Если тесты падают и после этого, это уже
находка: посмотрите, какой именно тест упал, и что он проверяет.

**После `git push` просит логин/пароль, а пароль не принимается**
GitHub больше не принимает обычный пароль для `git push` — нужен
Personal Access Token (создаётся в GitHub: Settings → Developer
settings → Personal access tokens) или настроенный SSH-ключ.

---

Если на каком-то шаге что-то пойдёт не так — опишите, что видите в
терминале или в браузере: текст ошибки почти всегда указывает на
причину.
