# Budget Tracker

Личный трекер финансов: расходы и доходы, бюджеты по категориям,
несколько кошельков в разных валютах, финансовые цели, регулярные
операции и аналитика — в интерфейсе, стилизованном под бумажный
бухгалтерский гроссбух.

Сделан как учебный проект для портфолио с явным акцентом на QA:
рядом с кодом лежат реальные найденные и исправленные баги, тест-кейсы
и регрессионный чек-лист — не только «работающая фича», но и процесс
проверки качества.

## Стек

- React (функциональные компоненты, хуки)
- Tailwind-утилиты для вёрстки
- [Recharts](https://recharts.org/) — график расходов по месяцам
- [lucide-react](https://lucide.dev/) — иконки
- `Intl.NumberFormat` — форматирование сумм под конкретную валюту без
  сторонних библиотек

## Функциональность

**Кошельки и валюты**
- Несколько независимых кошельков, каждый в своей валюте (₽, $, €, ₸ и др.)
- Кошельки не складывают и не конвертируют суммы друг в друга — это
  осознанное ограничение, см. «Известные ограничения» ниже

**Категории**
- Добавление, переименование, смена цвета, удаление
- Удаление категории не «теряет» связанные расходы — они помечаются
  как «Без категории» (см. BUG-001 в `BUG-REPORTS.md`)

**Записи**
- Расходы и доходы с датой, категорией (для расходов), описанием, суммой
- Полное редактирование существующей записи, не только суммы
- Поиск по описанию, фильтры по категории/типу/диапазону дат/превышению бюджета

**Бюджет**
- Лимит по каждой категории, прогресс-бар, индикация превышения
- «Остаток бюджета» и отдельно «Баланс месяца» (доход − расход)

**Финансовые цели**
- Название, целевая сумма, накопленная сумма с прогресс-баром

**Регулярные операции**
- Шаблон (название/сумма/категория/день месяца), баннер-подсказка
  применить его в текущем месяце

**Аналитика**
- Расходы за месяц и % к прошлому, средний расход в день, число
  операций, самый дорогой день, топ-3 категории

**Данные**
- Экспорт в JSON (полный бэкап) и CSV (операции кошелька)
- Импорт JSON с проверкой структуры файла перед заменой данных

**Настройки**
- Светлая/тёмная тема
- Переключаемое подтверждение перед изменением бюджета/цели и удалением категории

## Как запустить

> Подробный пошаговый гайд «с нуля», включая установку Node.js,
> частые ошибки и деплой — в **`SETUP.md`**. Ниже — краткая версия.

Текущая версия использует специфичный для Claude Artifacts API
`window.storage` (`get/set/delete/list`) для персистентности —
его нет в обычном браузере.

Чтобы превратить это в самостоятельный деплоящийся проект (Vite +
React), нужен один явный шаг адаптации:

1. Создать стандартный Vite-проект (`npm create vite@latest -- --template react`)
   и скопировать содержимое `src/` в него.
2. Заменить обращения к `window.storage.get/set` на реализацию поверх
   `localStorage` с тем же интерфейсом — пример адаптера см. в
   `storage-adapter.example.js` в этом репозитории.
3. Установить зависимости: `react`, `recharts`, `lucide-react`,
   `tailwindcss` (или подключить Tailwind через CDN для быстрого
   прототипа).
4. `npm run dev`.

Это сознательно вынесено как отдельный шаг, а не сделано «по умолчанию»
универсальным — так честнее показывать, в какой среде код был
фактически написан и протестирован.

## Архитектура

Логика разнесена на модули:

```
src/
├── components/   Header, WalletSwitcher, SettingsPanel, Balance,
│                 MonthlyChart, LedgerTooltip, Analytics,
│                 CategoryBudgetList, GoalsSection, RecurringBanner,
│                 ExpenseForm, ExpenseList, ConfirmDialog
├── hooks/
│   └── useBudgetStorage.js   загрузка, миграция версий storage,
│                             debounce-сохранение с id-guard
├── utils/
│   ├── dates.js       todayISO, monthKey, daysInMonth
│   ├── money.js        formatMoney, csvEscape, downloadFile
│   └── validation.js   validateAmount, isValidStoredShape, isDuplicateName
├── constants.js  категории по умолчанию, валюты, темы, ключи storage
└── App.jsx       тонкий контейнер: держит UI-состояние и бизнес-логику,
                  вычисляет производные данные, раздаёт их компонентам как props
```

`App.jsx` сознательно остаётся «толстым контейнером», а не россыпью
специализированных хуков — компоненты в `components/` полностью
presentational (получают данные и колбэки через props, ничего не
знают о storage или бизнес-правилах). Следующий разумный шаг —
вынести часть логики `App.jsx` (кошельки, категории, фильтры) в
отдельные хуки, если контейнер продолжит расти.

Исходный вариант в один файл (`budget-tracker.jsx`, ~1100 строк)
оставлен в репозитории как версия для превью в чате Claude — там
сборка модулей недоступна, весь код должен жить в одном файле.
`src/` — рабочая версия для реального репозитория.

## Тестирование

Ручное тестирование, структурированное, плюс автотесты сверху:

- **`TEST-CASES.md`** — 36 тест-кейсов (P0/P1/P2) с шагами и ожидаемым
  результатом: основной путь, валидация и edge-cases, второстепенное
  поведение (тема, доступность, границы месяца/года).
- **`CHECKLIST.md`** — короткий регрессионный чек-лист на 5–10 минут
  для прогона перед демо.
- **`BUG-REPORTS.md`** — 9 реально найденных и исправленных багов с
  шагами воспроизведения, root cause и описанием фикса. Все баги
  найдены через код-ревью проекта, ни один не выдуман задним числом.
- **Автотесты (Vitest + Testing Library)** — `npm test`:
  - `src/lib.js` — чистые функции без побочных эффектов
    (`validateAmount`, `isValidStoredShape`, `formatMoney`, `csvEscape`,
    `monthKey`, `daysInMonth`, `normalizeWallet`, `normalizeExpense`,
    `emptyBudgets`), покрытые unit-тестами в `src/__tests__/utils.test.js`.
  - `src/__tests__/App.test.jsx` — интеграционные тесты на рендер и
    пользовательские сценарии, сгруппированные по разделам приложения:
    - **Записи и категории** — добавление записи, отклонение суммы 0,
      удаление категории, импорт битого файла.
    - **Кошельки** — создание кошелька в другой валюте, занятое и пустое
      название, изоляция записей между кошельками.
    - **Финансовые цели** — добавление, валидация имени и суммы,
      правка накопленной суммы с пересчётом процента, отмена по Escape,
      удаление, диалог подтверждения при включённых подтверждениях.
    - **Регулярные операции** — добавление шаблона, валидация, баннер за
      текущий месяц и однократное применение, удаление шаблона.

    Часть тестов — регрессии на уже описанные баги (BUG-001, BUG-002,
    BUG-003, BUG-004, BUG-005 из `BUG-REPORTS.md`). Тесты проверены
    мутационно: намеренная поломка соответствующего кода в `App.jsx`
    роняет ожидаемый тест.

## Известные ограничения

- **Мультивалютность — только форматирование**, не конвертация.
  Кошелёк в USD и кошелёк в RUB существуют независимо и никогда не
  суммируются между собой.
- **Персистентность зависит от среды** (`window.storage` в Claude
  Artifacts) — см. «Как запустить».
- **Гонка сохранений** в storage смягчена дебаунсом и id-guard'ом
  (BUG-009), но не имеет строгой гарантии консистентности при
  параллельной работе в нескольких вкладках — вне рамок текущей
  итерации.
- Суммы округляются до целого числа при отображении (осознанное
  решение для читаемости в стиле гроссбуха, не баг).
