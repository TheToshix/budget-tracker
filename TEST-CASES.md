# Test Cases — Budget Tracker

Ручные тест-кейсы для регрессионного и функционального тестирования.
Приоритеты: **P0** — блокирующие/критичные пути, **P1** — важные
edge-cases и валидация, **P2** — второстепенное поведение и полировка.

Легенда статусов: ✅ Pass · ❌ Fail (см. BUG-REPORTS.md) · — Not run yet.

---

## P0 — Критический путь

### TC-001 — Добавление расхода
**Preconditions:** Открыто приложение, выбран кошелёк, есть хотя бы одна категория.
**Steps:**
1. В форме «Новая запись» оставить тип «Расход».
2. Указать сумму 500, категорию «Еда», описание «обед», сегодняшнюю дату.
3. Нажать «Добавить».
**Expected:** Запись появляется в списке «Записи за месяц», «Потрачено» и
остаток бюджета обновляются на 500.

### TC-002 — Добавление дохода
**Steps:** Аналогично TC-001, но переключить тип на «Доход», указать
источник «зарплата», сумму 50000.
**Expected:** Запись отмечена как доход (зелёная сумма со знаком «+»),
«Доход» и «Баланс месяца» обновляются, категория для дохода не требуется.

### TC-003 — Удаление записи
**Steps:** Навести на существующую запись → нажать иконку удаления (X).
**Expected:** Запись пропадает из списка, суммы (потрачено/баланс/бюджет
категории) пересчитываются немедленно.

### TC-004 — Редактирование суммы через полное редактирование записи
**Steps:** Нажать карандаш на записи → изменить сумму → «Сохранить».
**Expected:** Новая сумма отражена в списке и во всех агрегатах
(категория, месяц, аналитика).

### TC-005 — Данные сохраняются после перезагрузки страницы
**Steps:** Добавить расход → подождать ~1 секунду (за это время должен
пройти debounce-сохранения) → перезагрузить страницу/артефакт.
**Expected:** Добавленная запись присутствует после перезагрузки.

### TC-006 — Изоляция расходов между кошельками
**Steps:** Создать второй кошелёк «Путешествия» (другая валюта) →
добавить в нём расход → переключиться обратно на «Основной».
**Expected:** Расход из «Путешествий» не отображается и не учитывается
в «Основном», суммы и валюта показываются раздельно для каждого
кошелька.

### TC-007 — Переключение месяцев
**Steps:** Добавить расходы в текущем и в прошлом месяце (через дату в
форме) → переключаться стрелками между месяцами.
**Expected:** «Записи за месяц», разбивка по категориям и аналитика
показывают данные только выбранного месяца; график по месяцам всегда
показывает все 6 месяцев независимо от фильтра списка записей.

### TC-008 — Удаление категории с существующими расходами
**Preconditions:** Есть категория с минимум одним расходом (см. BUG-001).
**Steps:** Настройки → Категории → удалить категорию, у которой есть
расходы → подтвердить.
**Expected:** Категория пропадает из списка категорий и из графика;
расход остаётся в списке записей с меткой «Без категории»; сумма
расхода по-прежнему учитывается в общем «Потрачено».

### TC-009 — Повреждённые данные в storage
**Preconditions:** Возможность вручную задать значение по ключу
хранилища (например, через devtools или тестовый хук).
**Steps:** Положить в ключ текущей версии storage JSON вида
`{"categories":"broken","wallets":[]}` → перезагрузить приложение.
**Expected:** Приложение не падает; либо откатывается на дефолтные
данные, либо переходит к следующей по счёту версии storage (миграция).

## P1 — Валидация и граничные случаи

### TC-010 — Сумма расхода = 0
**Steps:** В форме «Новая запись» ввести сумму 0 → «Добавить».
**Expected:** Запись не создаётся, под формой появляется сообщение
«Сумма должна быть больше 0».

### TC-011 — Отрицательная сумма
**Steps:** Ввести -100 в поле суммы (если позволяет `input`) → отправить.
**Expected:** Запись не создаётся, отображается ошибка валидации.

### TC-012 — Очень большая сумма
**Steps:** Ввести сумму 999999999 → отправить.
**Expected:** Запись создаётся и корректно отображается с разделителями
разрядов (`Intl.NumberFormat`), без переполнения layout.

### TC-013 — Дробная сумма
**Steps:** Ввести сумму 149.99 → отправить.
**Expected:** Запись создаётся; отображение суммы округляется до целого
согласно `formatMoney` (это осознанное поведение — задокументировать в
README, не баг).

### TC-014 — Пустое описание
**Steps:** Оставить поле «Описание» пустым → отправить.
**Expected:** Запись создаётся с описанием по умолчанию — названием
категории для расхода или «Доход» для дохода.

### TC-015 — Пустое название кошелька
**Steps:** Открыть форму нового кошелька → оставить название пустым →
«Создать».
**Expected:** Кошелёк не создаётся, ошибка «Введите название кошелька».

### TC-016 — Пустое название категории
**Steps:** а) при создании — оставить поле пустым и нажать «Добавить»;
б) при переименовании — стереть название существующей категории и
кликнуть мимо поля.
**Expected:** В обоих случаях пустое название не сохраняется, показана
ошибка «Название категории не может быть пустым» / «Введите название
категории».

### TC-017 — Дубликат категории
**Steps:** Создать категорию «Еда», когда категория с таким названием
уже есть (с учётом регистра и пробелов).
**Expected:** Категория не создаётся, ошибка «Категория с таким
названием уже есть».

### TC-018 — Дубликат кошелька
**Steps:** Создать кошелёк с именем, совпадающим с существующим.
**Expected:** Кошелёк не создаётся, ошибка «Кошелёк с таким названием
уже есть».

### TC-019 — Enter при редактировании бюджета/цели
**Steps:** Начать редактирование суммы бюджета категории → ввести новое
значение → нажать Enter.
**Expected:** Значение сохраняется ровно один раз (если включено
подтверждение действий — диалог показывается один раз, не дважды).

### TC-020 — Escape при редактировании бюджета/цели
**Steps:** Начать редактирование суммы бюджета → изменить значение →
нажать Escape.
**Expected:** Редактирование закрывается, значение остаётся прежним
(изменение не применяется).

### TC-021 — Удаление категории, выбранной в форме добавления записи
**Steps:** Выбрать категорию в форме «Новая запись» → не отправляя,
удалить эту категорию в настройках → вернуться к форме и отправить.
**Expected:** Категория в форме автоматически переключилась на
существующую; отправка формы не создаёт запись со ссылкой на удалённую
категорию.

## P2 — Второстепенное поведение

### TC-022 — Тёмная тема
**Steps:** Настройки → Тема → «Тёмная».
**Expected:** Фон, текст, границы и цвета категорий/графика меняются на
тёмный набор без потери читаемости и контраста.

### TC-023 — Сохранение темы после перезагрузки
**Steps:** Включить тёмную тему → перезагрузить приложение.
**Expected:** Тема остаётся тёмной (сохранена в storage вместе с
остальными настройками).

### TC-024 — Мобильный экран
**Steps:** Открыть приложение на ширине ~375 px.
**Expected:** Все формы, график и таблица записей остаются usable без
горизонтального скролла; кнопки достаточного размера для тапа.

### TC-025 — Навигация с клавиатуры
**Steps:** Пройти по интерфейсу только клавишей Tab, включая кнопку
настроек, переключатель кошельков, форму добавления записи.
**Expected:** Виден фокус (`focus-visible` outline) на каждом
интерактивном элементе, порядок обхода логичен.

### TC-026 — Длинное название категории
**Steps:** Создать категорию с названием из 60+ символов.
**Expected:** Название усечено (`truncate`) там, где не помещается, без
поломки вёрстки строки.

### TC-027 — Длинное описание записи
**Steps:** Добавить расход с описанием из 200+ символов.
**Expected:** В списке записей описание усекается с `truncate`,
полный текст не ломает строку.

### TC-028 — Большое количество операций
**Steps:** Добавить 100+ записей в одном месяце (через импорт JSON или
вручную).
**Expected:** Список, фильтры и аналитика продолжают работать без
заметных подвисаний; сортировка по дате сохраняется.

### TC-029 — Переключение валюты между кошельками
**Steps:** Создать кошельки в RUB, USD и EUR → переключаться между ними.
**Expected:** Суммы форматируются в соответствующей валюте
(`Intl.NumberFormat` + `style: currency`), кошельки не складывают и не
конвертируют суммы между собой.

### TC-030 — Граница месяца (переход между месяцами)
**Steps:** Добавить запись датой 31 января и датой 1 февраля →
переключаться между месяцами.
**Expected:** Каждая запись попадает строго в свой месяц, ни одна не
задваивается и не пропадает на границе.

### TC-031 — Граница года
**Steps:** Добавить запись датой 31 декабря и датой 1 января следующего
года → просмотреть график «Динамика по месяцам», переключаясь через
границу года.
**Expected:** Год корректно инкрементируется/декрементируется при
навигации, записи не путаются между годами.

### TC-032 — Регулярная операция подхватывается в новом месяце
**Steps:** Создать регулярную операцию (например, «Проездной», день 5)
→ переключиться на следующий месяц.
**Expected:** В баннере «Регулярные операции» появляется предложение
добавить операцию за новый месяц; после нажатия «Добавить» создаётся
запись датой 5-го числа этого месяца.

### TC-033 — Финансовая цель — редактирование и подтверждение
**Preconditions:** Включено «Подтверждение действий» в настройках.
**Steps:** Изменить накопленную сумму по цели.
**Expected:** Появляется диалог подтверждения с точным описанием
изменения; при отмене — значение не меняется, при подтверждении —
применяется.

### TC-034 — Экспорт/импорт JSON
**Steps:** Экспортировать JSON → изменить данные в приложении → импортировать
ранее экспортированный файл, подтвердить замену.
**Expected:** Состояние приложения возвращается к экспортированному
снэпшоту (кошельки, категории, записи, настройки).

### TC-035 — Импорт повреждённого JSON
**Steps:** Попытаться импортировать файл, не являющийся валидным
экспортом (например, произвольный текстовый файл или JSON с неверной
структурой).
**Expected:** Показывается сообщение об ошибке импорта, текущие данные
приложения не изменяются.

### TC-036 — Экспорт CSV
**Steps:** Экспортировать CSV текущего кошелька → открыть файл.
**Expected:** Файл содержит заголовок и строки со всеми операциями
кошелька (дата, тип, категория, описание, сумма, валюта), корректно
экранированные поля с запятыми/кавычками.
